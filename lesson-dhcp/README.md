# Конспект: Протокол динамической настройки узлов (DHCP)

---

## 1. Назначение и функции DHCP

**DHCP (Dynamic Host Configuration Protocol)** — протокол прикладного уровня, предназначенный для автоматической конфигурации сетевых параметров узлов стека TCP/IP:
- Выдача индивидуального IPv4-адреса и сетевой маски;
- Передача адреса основного шлюза (Default Gateway);
- Предоставление адресов DNS-серверов, локального домена и сопутствующих параметров.

**Преимущества автоматизации:**
Ручная настройка требует от администратора постоянного учёта занятых адресов и ручного ввода параметров на каждом ПК. DHCP исключает вероятность случайного дублирования IP-адресов за счёт централизованного управления доступными адресными пулами.

---

## 2. Эволюция: предшественники протокола

1. **RARP (Reverse Address Resolution Protocol):**
   - Работал по принципу «определение IP по аппаратному MAC-адресу» через широковещательный запрос клиента к базе данных сервера.
   - *Недостатки:* требовал отдельный сервер в каждом сегменте сети, обязательную ручную регистрацию MAC-адресов и не мог передавать дополнительные параметры (маску, шлюз, DNS).

2. **BOOTP (Bootstrap Protocol):**
   - Разрабатывался для сетевой загрузки бездисковых станций: помимо IP передавал путь к файлу загрузки и адрес TFTP-сервера.
   - Ввёл механизм **Relay (агенты пересылки)**, что позволило одному серверу обслуживать несколько подсетей.
   - *Недостатки:* фиксированный размер пакета для опций и необходимость статически прописывать таблицы сопоставления.

> **Совместимость:** Протокол DHCP построен на базе BOOTP и расширяет его возможности. Сервер DHCP умеет обслуживать старых клиентов BOOTP, но обратная совместимость не поддерживается.

---

## 3. Режимы распределения адресов

DHCP работает строго по архитектуре **клиент–сервер**. Администратор выделяет диапазон доступных значений — **пул адресов (Address Pool)**.

| Режим работы | Принцип назначения адреса |
| :--- | :--- |
| **Ручное статическое назначение** | Администратор жестко привязывает конкретный IP-адрес к MAC-адресу клиента. Сервер всегда возвращает этой машине только фиксированный адрес. |
| **Автоматическое статическое назначение** | Сервер самостоятельно выделяет свободный IP-адрес из пула при первом запросе и навсегда закрепляет его за данным клиентом. |
| **Динамическое распределение** | Адрес выдаётся узлу во временное пользование на **срок аренды (Lease Time)**. По истечении срока освободившийся адрес возвращается в пул. |

**Экономия адресного пространства:**
Динамический пул позволяет обслуживать больше устройств, чем фактически доступно свободных адресов, если пользователи подключаются не одновременно (например, мобильные сотрудники или ноутбуки в учебных аудиториях).

---

## 4. Маршрутизация DHCP: Сервер и Relay-агент

- Если клиент и сервер находятся **в одной подсети**, обмен сообщениями происходит напрямую через широковещательные пакеты.
- Для отказоустойчивости в локальный сегмент часто добавляют **резервный DHCP-сервер**.
- Если сервер расположен **в другой подсети**, маршрутизатор или хост-посредник выполняет роль **связного DHCP-агента (DHCP Relay Agent)**: он перехватывает широковещательный запрос клиента, упаковывает его в одноадресный (unicast) пакет и направляет целевому DHCP-серверу.

---

## 5. Алгоритм получения сетевых настроек (DORA)

Процесс взаимодействия состоит из 4 базовых шагов:

1. **DHCP-поиск (Discover):** Клиент при старте отправляет ограниченный широковещательный запрос (Broadcast `255.255.255.255`), разыскивая серверы в сети.
2. **DHCP-предложение (Offer):** Все доступные серверы (напрямую или через relay) предлагают клиенту свободный IP-адрес и конфигурационные параметры.
3. **DHCP-запрос (Request):** Клиент выбирает наиболее подходящее предложение (обычно первое поступившее) и рассылает широковещательное уведомление о сделанном выборе.
4. **DHCP-квитанция (Acknowledge / ACK):** Выбранный сервер фиксирует аренду и высылает подтверждение клиенту. Остальные серверы аннулируют свои предложения и возвращают предложенные адреса в пул.

---

## 6. Срок аренды (Lease Time)

- **Настройка срока:** Длительность аренды зависит от профиля сети: короткая аренда (часы) актуальна для публичных и учебных Wi-Fi сетей, длительная (дни или недели) — для стабильных корпоративных сетей.
- **Продление:** Клиент инициирует процедуру продления аренды задолго до её истечения (обычно при достижении 50% и 87.5% срока). Если сервер не отвечает, клиент опрашивает другие серверы или теряет IP-адрес, переходя в автономный режим.

---

## 7. Ограничения динамической адресации

Постоянная сменяемость IP-адресов создает трудности:
1. **Преобразование имён (DNS):** Требуется применение технологии **Dynamic DNS (DDNS)** для автоматической синхронизации записей DNS при смене адреса узла.
2. **Удаленный мониторинг:** Сложно собирать телеметрию и подключаться к устройству с плавающим адресом.
3. **Безопасность и фильтрация:** Правила пакетных фильтров и списков ACL привязаны к IP-адресам.

*Решение:* Критически важным узлам (маршрутизаторы, серверы, сетевые принтеры, интерфейсы мониторинга) всегда назначают **постоянные статические IP-адреса**.
